# WODLog 운동 기록 리서치와 UI 설계

[GitHub 리서치 이슈와 카탈로그](https://github.com/rsy-dev/WODLog/issues/19) · [모바일 목업](wodlog-recording-prototype.html)

## 설계 결론

**기록은 빠르게, 비교는 운동 조건이 확인된 경우에만.** 오늘 화면에서 세션을 열고 근력 세트 또는 WOD 결과를 바로 기록한다. 이름 있는 운동을 다시 할 때는 지난 결과가 아니라 운동 구성만 가져온다. 운동 후에는 수행한 버전과 결과를 함께 볼 수 있어야 한다.

## WOD는 진행 방식과 점수 규칙이 독립적이다

CrossFit은 AMRAP, EMOM, Chipper, Couplet, Rx’d를 별개 용어로 설명한다. WODLog에는 **진행 방식**, **점수 규칙**, **출처 컬렉션**, **실제 수행 버전**을 독립 필드로 둔다. 예를 들어 Fran은 Girls 컬렉션의 couplet이며 점수는 완주 시간이다. Chipper와 couplet은 검색에 쓰고 입력 필드는 점수 규칙이 결정한다. [CrossFit 공식 용어집](https://www.crossfit.com/essentials/crossfit-terms-explained)

| 유형·예시 | 빠른 기록 필드 | 상세 입력 및 비교 조건 |
|---|---|---|
| For Time · Fran, Grace | 완주 시간 | 제한시간이 있으면 완주 / 타임캡 / 중단을 선택. 시간과 캡까지 누적한 반복 수를 별도 필드로 저장 |

### 기록의 최소 단위

- **세션**은 날짜와 여러 블록을 묶는다. 예시는 “Back Squat 3세트 → WOD Cindy”. 필요하면 근력·WOD·보조 블록을 추가한다.
- **근력**은 동작과 실제 세트별 중량·반복·성공 여부를 저장한다. 이전 세트의 숫자는 복사 가능하지만 성공 여부는 새 기록에서 다시 확인한다. 무중량과 미입력을 구분한다. 실제 1·3·5RM과 Epley 추정 1RM에는 각각 산출 기준과 원본 세트 링크를 표시한다. 계산과 유효성은 [#16 백엔드 계약](https://github.com/rsy-dev/WODLog/issues/16)을 사용한다.
- **WOD**는 처방 스냅샷과 실제 결과를 같이 기록한다. 먼저 템플릿·최근 기록·직접 입력 중 선택한다. 운동 설정은 Rx / Scaled / Foundations / 사용자 변형 / 미확인 중 명시하고, 중량, 동작 변경, 거리, 높이, 팀 크기와 구간 순서를 필요에 따라 수정한다.
- **캡에서 미완료**는 완료 시간에 캡 시간을 넣지 않는다. 예를 들어 Open 26.1은 완주하면 시간, 캡에 걸리면 완료 반복 수와 점수표가 지정하는 타이브레이크를 기록한다. 중단은 타임캡과도 다르다. [2026 Open 점수표](https://games.crossfit.com/workouts/open/2026/1?scaled=2)
- **기록 수정**은 그날 수행한 처방만 수정한다. 카탈로그 개정과 닮은 동작 이름으로 과거 기록을 소급 변경하지 않는다. 과거 자유 텍스트는 원문을 보존하고 사용자 확인을 거친 경우 구조화한다.

### 비교 규칙

- 세션끼리 비교하기 전에 결과 종류, 제한시간, 동작 ID와 변형, 과제 순서·반복·라운드, 실제 중량과 장비, 수행 방식이 같은지 확인한다. 필요한 조건 중 하나라도 미확인이면 이유를 보여준다. UI는 [#17 호환성 계약](https://github.com/rsy-dev/WODLog/issues/17)이 확정한 결과를 표시한다.
- Cindy의 20분 동일 구성 기록은 라운드와 추가 반복을 비교한다. 다른 지속 시간의 AMRAP은 독립 기록으로 남긴다.
- Murph는 조끼 중량, 중간 동작을 나눈 방식, 달리기 거리, 대체 동작을 보존한다. 예를 들어 조끼 없이 분할한 기록과 조끼를 입고 분할하지 않은 기록을 하나의 PR 계열로 합치면 변화 원인을 해석하기 어렵다. [Murph 공식 처방 및 변형](https://www.crossfit.com/benchmark/murph)
- 유사 동작은 그룹의 반복량과 중량 볼륨 추이에 사용한다. Back Squat와 Front Squat의 PR은 각 동작에 귀속한다. 런·로우의 거리와 바벨 볼륨은 각각 표시한다.

## 카탈로그 자산 및 업데이트 규칙

공식 목록을 2026-11-19에 확인했다. CSV의 키는 편집용 식별자이며 앱에 넣을 때 기존 카탈로그 ID에 매핑한다. 공개 URL과 이름 중심의 인덱스이므로 선수 개인정보, 현지 박스 자유 와드, 모든 Open 시즌의 점수표 본문은 포함 범위 밖이다.

- **Hero & Tribute 254개**. 공식 인덱스 전체 카드의 이름과 링크를 기록했다. Paul Pena와 Scooter가 공식 카드에서 동일 상세 URL을 참조해 두 이름을 보존하고 확인 필요로 표시했다. [Hero & Tribute 공식 인덱스](https://www.crossfit.com/heroes)
- **동작 120개**. 공식 동작 페이지의 117개와 WOD에서 쓰는 Run·Bike·Swim을 수록했다. 기초 9동작, 일부 검색 별칭, 출처 URL을 함께 저장했다. Strict / Kipping, Bar / Ring, Hang / Ground, Power / Squat은 실제로 구별하는 변형이며, 별칭은 검색에만 사용한다. [동작 공식 인덱스](https://www.crossfit.com/crossfit-movements)
- **대표 벤치마크 40개**. Girls, 고전 테스트 및 Open 채점 사례의 검색용 인덱스와 점수 종류. 대회 전체는 시즌 아카이브에서 종목·디비전·점수표를 확인한 뒤 버전 단위로 등록한다. [초기 Girls](https://library.crossfit.com/free/pdf/13_03_Benchmark_Workouts.pdf) · [The New Girls](https://library.crossfit.com/free/pdf/27_04_new_girls.pdf) · [Open 공식 아카이브](https://games.crossfit.com/workouts/open)
- **템플릿 승격**은 이름·출처 → 처방과 점수 규칙 확인 → 버전 고정 → 비교 허용 순으로 한다. 출처 URL 하나가 이름이나 버전을 확정하지 못하면 등록은 하되 빠른 복제와 자동 PR 적용을 보류한다.
- **템플릿 메타데이터**는 안정 키, 버전, 컬렉션, 원문 이름·별칭·출처, 파트·동작 순서, 점수 규칙, 변형별 처방을 사용한다. 동작 자산에는 기준 이름, 장비, 동작 그룹, 변형, 허용 입력 종류를 추가할 수 있다.

- **구조화 예시 11개**는 [JSON 템플릿](wodlog-template-seed.json)에 저장했다. 운동 순서, 규정 중량과 장비, 제한시간, 점수 집계 규칙을 확인할 수 있다.

## UI 설계 기준

1. **오늘**은 선택 날짜의 요약과 세션, 한 개의 주요 기록 버튼을 보여준다. 이전 세션 카드를 탭하면 WOD 결과와 세트 기록이 바로 열린다.
2. **세션**은 근력과 WOD 블록을 같은 화면에 둔다. 근력에서는 세트 복사와 추가, WOD에서는 최근·벤치마크·직접 입력을 제공한다.
3. **WOD 결과 편집기**는 제목과 수행 버전을 먼저 보여주고 점수 유형에 맞는 입력만 연다. 세부 처방은 한 단계 아래에서 수정한다. 저장 성공 뒤 세션 요약에 결과가 나타난다.
4. **라이브러리**는 이름과 별칭으로 검색하며 즐겨찾기·최근·Girls·Hero·Open 범위를 선택할 수 있다. 검색 결과에 점수 방식이 확인된 경우 표시한다. 처방이 검증된 템플릿만 운동 구성 복사를 지원한다.
5. **성장**은 동작 탭과 WOD 탭에서 최신·직전 기록, 변화, 추이를 본다. 같은 조건의 이전 결과가 없으면 그 이유와 원본 기록을 보여준다.

### 디자인 수용 기준

- Cindy에서 라운드와 끝에 남은 반복을 입력하고 검토할 수 있다.
- For Time은 완주 시간·타임캡 시 반복 수·중단 상태를 저장 전 명확히 구별한다.
- Scaled로 중량을 변경했을 때 동일 이름의 Rx 기록이 자동 비교에 포함되지 않는다.
- 연속 근력 세트 기록에서 중량과 반복을 재사용할 수 있고, 단위 변경 뒤에도 과거 중량의 기준값이 보존된다.
- 320px 화면과 RTL에서 동작 이름, 결과 단위, 이동 아이콘, 입력 버튼을 읽을 수 있다.
